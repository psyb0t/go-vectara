# go-vectara

Unofficial Go client for the Vectara API v2, generated from the OpenAPI document Vectara publishes. If you only want to use the client from an agent, read [.agents/skills/go-vectara/SKILL.md](.agents/skills/go-vectara/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `vectara`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://docs.vectara.com/vectara-oas-v2.yaml` to `api/openapi.yaml`. `scripts/patch-spec.sh` runs `go tool patch-spec` to write `api/openapi.fixed.yaml`. oapi-codegen with `config.yaml` generates the full client, then `scripts/split-gen.sh` splits it into `client_*.gen.go` files.

## Stack

- Go 1.26.9.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client_*.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, patch wrapper, output splitting, lint and security scan scripts.
- `internal/cmd/patch-spec/`: the spec repair tool, invoked by the patch wrapper.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Use Vectara's public `vectara-oas-v2.yaml` spec.
- `HallucinationCorrectionRequest.query` has an invalid boolean `required: false`. The patch tool removes this property keyword before generation.
- `JsonSchemaObject.additionalProperties` gets `x-go-name: AllowsAdditionalProperties` to avoid colliding with the generator's `AdditionalProperties` map. Preserve its JSON key and unknown keyword roundtrip behavior.
- The patch tool replaces the spec's dummy Slack bot token example with a placeholder. GitHub push protection rejects the original value in generated comments, so keep that replacement.
- The client is split because the full spec produces a large source file. Remove stale split output through the generation script rather than editing generated files.
- The server is `https://api.vectara.io`. Generated paths include `/v2`; do not append it to the base URL.
- Set `x-api-key` or an appropriate bearer token with a request editor. Security constants do not attach credentials.
- The `number` to `float64` mapping keeps unformatted scores and other numbers from becoming `float32`.
- Method names follow the spec's operation IDs. Check generated signatures before changing examples.
- Streaming endpoints need raw response handling, including closing the response body. Parsed methods read the full body.
- Pagination, retries and OAuth token refresh belong to the caller.
- `make generate` downloads the current spec. Review the generated diff after regeneration.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
